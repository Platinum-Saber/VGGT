\begin{abstract}
VGGT (Wang et al., CVPR 2025) is a 1.2\,B-parameter feed-forward transformer that predicts, from one to hundreds of
images, all key 3D attributes of a scene: camera parameters, depth maps, point maps and point tracks.
We re-implemented the original VGGT package without modifications: the same module layout, class and function names,
defaults and parameter names as the official code, including the tracking head. Meta's released \texttt{VGGT-1B} weights
load unchanged. With identical weights the re-implementation reproduces the official outputs \emph{exactly} (maximum
absolute difference $0$ for cameras, depth, point maps, confidences and tracks), both with randomised weights and with the
released checkpoint on real images. VGGT-1B is not retrained. Instead we test the paper's claims with the released model:
inference speed, reconstructions of real example scenes (inspected in an interactive 3D viewer), and accuracy against exact
ground truth on rendered scenes, compared with a classical SIFT + 5-point RANSAC baseline.
\end{abstract}

\section{Introduction}

VGGT~\cite{vggt} replaces the classical, optimisation-heavy structure-from-motion (SfM) pipeline with a single forward
pass of a large transformer. Given $N$ images $(I_i)_{i=1}^N$ it predicts
\begin{equation}
  f\big((I_i)_{i=1}^{N}\big) = \big(\mathbf{g}_i,\, D_i,\, P_i,\, T_i\big)_{i=1}^{N},
\end{equation}
i.e.\ per frame the camera parameters $\mathbf{g}_i$, a depth map $D_i$, a point map $P_i$ expressed in the coordinate frame
of the first camera, and point tracks $T_i$. The paper reports state-of-the-art results on camera pose estimation, multi-view
depth, point-map estimation and tracking, often outperforming optimisation-based methods while running in about a second.

\paragraph{Goal of this work.} Re-implement the original VGGT code faithfully, verify that the re-implementation is exact,
and check whether the paper's claims hold for the released model.

\paragraph{Scope.} The original model was trained on 17 datasets using 64 A100 GPUs for nine days; retraining it is out of
scope. All experiments use Meta's released \texttt{facebook/VGGT-1B} weights, run on a free Kaggle GPU (NVIDIA Tesla T4).

\paragraph{Contributions.}
\begin{enumerate}[leftmargin=*,itemsep=1pt]
  \item A re-implementation of the full original package (aggregator, camera, depth, point and track heads, utilities) with
        the official layout and parameter names, so the released checkpoint loads with \texttt{strict=True}.
  \item A bit-exact verification against the official implementation, with random weights and with the real
        \texttt{VGGT-1B} weights on real images, for all outputs including tracks.
  \item A demo that exports depth, point clouds, cameras and tracks, with a self-contained interactive 3D viewer.
  \item A ground-truth evaluation of the released model on rendered scenes with exact depth, points and cameras, using the
        paper's metrics and a classical baseline.
\end{enumerate}

\paragraph{Patchifier and tokens.} Images are normalised with ImageNet statistics and patchified by DINOv2 ViT-L/14 with
register tokens (24 blocks, 1024 channels). Positional embeddings are bicubically interpolated to the input aspect ratio.
For every frame, one camera token and four register tokens are concatenated to the patch tokens. Two sets of these
tokens are learned: one for the first frame and one for all others, which identifies the reference frame.

\paragraph{Alternating-Attention (AA).} The aggregator consists of $L=24$ pairs of transformer blocks. A
\emph{frame-wise} block reshapes tokens to $(B\!\cdot\!S, P, C)$ so attention is restricted to one image; a
\emph{global} block reshapes to $(B, S\!\cdot\!P, C)$ so all tokens of all frames attend to each other. Blocks are pre-norm
ViT blocks with 16 heads, 2D rotary position embeddings (RoPE, base frequency 100; special tokens receive position 0),
QK-normalisation and LayerScale ($\gamma_0 = 0.01$). The outputs of the frame and global block of a layer are concatenated to
$2C = 2048$ channels and passed to the heads.

\paragraph{Camera head.} The camera tokens of the last layer are refined iteratively (4 iterations). In each iteration the
current pose estimate (initialised with a learned ``empty'' token) is embedded and used to produce shift, scale and gate
parameters for adaptive layer normalisation of the camera tokens; four self-attention blocks across frames and an MLP
then predict an additive update. The 9-dimensional encoding is
$\mathbf{g} = [\mathbf{t}\in\mathbb{R}^3,\; \mathbf{q}\in\mathbb{R}^4,\; (\text{fov}_h, \text{fov}_w)]$ (translation,
unit quaternion, field of view; principal point at the image centre), with a ReLU on the field of view.

\paragraph{Dense heads.} Two DPT heads~\cite{dpt} read patch tokens from layers $\{4, 11, 17, 23\}$, project and resize them to
four scales ($\times4, \times2, \times1, \times\tfrac12$), fuse them coarse-to-fine and upsample to full resolution. Depth uses
an $\exp$ activation, point maps the inverse-log activation $\operatorname{sign}(y)(e^{|y|}-1)$. A final channel predicts an
aleatoric confidence $\Sigma = 1 + e^{c}$.

\paragraph{Track head.} A third DPT head in feature-only mode turns the tokens into 128-channel tracking features at half
resolution. A CoTracker/VGGSfM-style predictor starts every frame at the query positions of frame 1 and refines them for 4
iterations: it samples a 7-level correlation pyramid (radius 4) around the current positions, embeds the motion relative to
the query frame, and lets an update transformer (time attention per track, space attention through 64 virtual tracks) predict
coordinate and feature updates. Visibility and confidence are predicted from the final track features.

\paragraph{Code layout.} The package mirrors the official one: \texttt{vggt/models/} (model and aggregator),
\texttt{vggt/layers/} (attention, block, RoPE, DINOv2 ViT), \texttt{vggt/heads/} (camera, DPT, track heads and track modules),
\texttt{vggt/utils/} (pose encoding, rotation, geometry, image loading). Only the official \texttt{vggt/dependency/} folder
(VGGSfM tracker, bundle adjustment and COLMAP export used by the official COLMAP demo) is not included; it is post-processing
outside the network. The companion document \texttt{code\_walkthrough.pdf} explains every phase in detail.

\subsection{Evaluation metrics}
\label{sec:metrics}
\begin{itemize}[leftmargin=*,itemsep=1pt]
  \item \textbf{Camera pose:} for every ordered pair of frames, the relative rotation error (RRA) and the angle between
        relative translation directions (RTA), in degrees. AUC@$\tau$ is the area under the accuracy curve of
        $\max(\text{RRA},\text{RTA})$ for thresholds $1,\dots,\tau$ degrees. We also report RRA@15/RTA@15 (fraction
        below $15^\circ$) and median errors.
  \item \textbf{Depth:} AbsRel and $\delta < 1.25$ after one median scale per sequence.
  \item \textbf{Point maps:} mean Euclidean error after a least-squares similarity (Umeyama) alignment, in normalised
        scene units.
\end{itemize}

\section{Verification of the implementation}
\label{sec:verify}

\subsection{Numerical equivalence with the official code}

Module and parameter names follow the official release, so a state dict can be moved between the two implementations
with \texttt{load\_state\_dict(strict=True)}. We performed three equivalence tests (Table~\ref{tab:equiv}).

\begin{enumerate}[leftmargin=*,itemsep=1pt]
  \item \textbf{Random weights, CPU} (\texttt{tests/test\_equivalence.py}): a reduced configuration (DINOv2-S patchifier,
        4 AA layers, 2-block camera trunk, all heads including tracking) with \emph{all} parameters randomised, on non-square
        input ($182\times252$, 3 frames, 3 query points), which exercises positional-embedding interpolation, RoPE, AA, the
        camera trunk, the DPT heads and the tracker.
  \item \textbf{Full configuration}: the default VGGT-1B models of both implementations have identical parameter names and
        shapes ($1{,}256{,}537{,}516$ parameters).
  \item \textbf{Released weights}: the \texttt{facebook/VGGT-1B} checkpoint loaded with \texttt{strict=True} into both
        implementations, evaluated in fp32 on the first 2 images of the official \texttt{examples/kitchen} scene
        ($350\times518$) with 3 query points, on a CPU. The Kaggle notebook repeats this on a GPU with 8 images.
\end{enumerate}

\noindent The implementation is therefore functionally identical to the released model: every output of VGGT-1B is produced
unchanged by this code.

\paragraph{A subtle detail.} An early version differed by up to $5\times10^{-3}$ in the DPT outputs. The cause is the
residual unit of the official DPT head, which applies an \emph{in-place} ReLU to its input before the skip connection; the
skip path therefore carries $\operatorname{relu}(x)$ rather than $x$. The released weights were trained with this behaviour,
so it must be replicated. Similarly, the tracker's bilinear sampler detaches the sampling coordinates and the attention
blocks of the update transformer take the residual after the first LayerNorm; both are kept.

\section{Checking the claims against exact ground truth}
\label{sec:gt}

\subsection{Rendered test scenes}

Real benchmarks (CO3D, RealEstate10K, DTU, ETH3D) are too large for a free GPU session, so we wrote a procedural ray-caster
(\texttt{evaluation/synthetic.py}) that produces scenes with exact ground truth. Each scene is a closed room
(inward-facing walls) with 3--6 random spheres and boxes. Surfaces have solid, i.e.\ 3D-consistent, textures
(per-object colour, sinusoidal bands, checkerboards) with fixed Lambertian shading, so appearance is consistent across views
and supports matching. Cameras are placed on an arc around the scene centre ($30$--$100^\circ$ spread) looking at a jittered
target, with field of view $50$--$75^\circ$. Each view is $518\times518$ pixels with exact depth, points, intrinsics and
extrinsics, normalised like the official training code (world = first camera, mean point distance 1). We evaluate 50 scenes
with 8 views each; VGGT-1B never saw such scenes, so this is a zero-shot test on an unusual (synthetic) domain.

\subsection{Protocol}

\texttt{evaluation/evaluate\_pretrained.py} runs VGGT-1B (fp16 autocast for the aggregator, heads in fp32, as in the
official README) on the first $S\in\{2,4,8\}$ views of every scene and computes the metrics of Sec.~\ref{sec:metrics}.
Point maps are evaluated twice: from the point head, and by unprojecting the predicted depth with the predicted cameras.
The classical baseline estimates the relative pose of every ordered pair with SIFT, Lowe's ratio test and the 5-point
algorithm in RANSAC (OpenCV), \emph{given the ground-truth intrinsics}; failed pairs count as $180^\circ$ error.

\section{Interactive 3D viewer}

\texttt{demo\_pretrained.py} runs VGGT-1B on a folder of images and writes depth maps, a coloured point cloud
(\texttt{points.ply}), the cameras (\texttt{cameras.json}), track visualisations and \texttt{viewer.html}. The viewer is a
single HTML file (three.js from a CDN, data embedded): it shows the point cloud from depth + cameras or from the point head,
the predicted camera frustums with their images, and 3D tracks obtained by lifting each 2D track with that frame's depth
(for a static scene a correct track collapses to one 3D point, so the 3D tracks visualise multi-view consistency).
A slider keeps the top $x\,\%$ of points by confidence, and clicking an image looks through that camera. The notebook shows
the viewer inline for the official kitchen and room examples.

\paragraph{Limitations.}
\begin{itemize}[leftmargin=*,itemsep=1pt]
  \item No retraining: the released weights are evaluated, not reproduced from data.
  \item The ground-truth test uses a synthetic indoor domain, not the paper's real-world benchmarks; it tests geometric accuracy
        under known ground truth, and is out of the training distribution for VGGT-1B.
  \item A two-view classical baseline instead of full SfM pipelines (COLMAP, VGGSfM); the baseline is given ground-truth intrinsics.
  \item The official bundle-adjustment and COLMAP-export code (\texttt{vggt/dependency/}) is not part of this re-implementation.
\end{itemize}

\section{Conclusion}

We re-implemented the original VGGT package, including the tracking head, with the official module layout and parameter
names, and showed that it is numerically identical to the official implementation: bit-exact with randomised weights and
with the released 1.2\,B-parameter checkpoint on real images, for cameras, depth, point maps, confidences and tracks. It can
therefore be used as a drop-in replacement for the official package. With the released weights the model runs in seconds on
a T4 and reconstructs real scenes coherently. The ground-truth evaluation on rendered scenes, run in the Kaggle notebook,
quantifies pose, depth and point-map accuracy against a classical baseline.

\paragraph{Reproducibility.} \texttt{vggt/} (model, same layout as the official package), \texttt{tests/} (equivalence tests),
\texttt{demo\_pretrained.py} and \texttt{scripts/export\_viewer.py} (exports and 3D viewer), \texttt{evaluation/} (rendered
ground truth, metrics, SIFT baseline), \texttt{notebooks/kaggle\_vggt.ipynb} (all experiments on a Kaggle GPU), and
\texttt{results/} (JSON results).
